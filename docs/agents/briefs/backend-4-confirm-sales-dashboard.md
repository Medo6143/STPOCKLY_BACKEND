## 3. Binding design and contract
- **I5 confirm:** `docs/design/backend.md` §11 steps 1–11 exactly (invoice `FOR UPDATE`, idempotent repeat, supplier find-or-create, products locked with one `SELECT ... WHERE id = ANY(@ids) ORDER BY id FOR UPDATE`, new products from §10.5, `IStockService` movements `InvoiceReceipt` with `ProductUnit.ToBase()`, alias upsert, `invoice.Confirm`, after-commit cache bump and status cache). §17.1 items 3, 11, 12 apply.
- **S1–S3 sales:** contract §7. Follow the same transaction pattern as confirm: rule 3 idempotency (status/`clientRequestId` check + row lock + unique index on `sale_item_id`), rule 4 lock order (sale first, then products with the same ordered `FOR UPDATE` statement), `IStockService` movements with reason `Sale` and negative quantity, negative stock never blocks and is reported as `warnings`, `list_unit_price` and `unit_price` stored per line, `line_total` rounded to 2 decimals away from zero (§17.1 item 6), archived product → `400 Sale.ArchivedProduct`. Repeat `clientRequestId` → `200` with the existing sale, no new movements. S2 paged newest first with optional `from`/`to` (index documented). S3 `404 Sale.NotFound` for missing or other shop.
- **P12 lookup:** contract §5 P12 and §10 item 12: product and unit barcodes of non-archived products, exact match.
- **D1/D2:** contract §8. D1 cached 2 minutes per shop with the catalog version key (`docs/design/redis.md`, add the key there); "today" is the Africa/Cairo calendar day via `IClock` (no `DateTime.Now`). D2 per ADR-0004 as a hint: confirmed invoice lines with `expiry_date` within `days` whose product still has stock, soonest first, paged.
- Read `docs/erd.md` for the sale tables and indexes; add a migration for anything missing and read its SQL.

## 4. Critical rules (copied from AGENTS.md)
- 1–6: only `IStockService` changes `Product.Quantity`, in the same transaction as a new `StockMovement`; movements append-only; confirm and sale idempotent; lock order; base-unit quantities via `ToBase()`; money `numeric(18,2)`.
- 8–10: tenant from the JWT, wrong tenant → 404.
- 19: the AI never changes stock.
- 20: `POST /sales` requires `clientRequestId`.
- 21–25: cache through the interfaces, prefix, TTL, invalidate **after** commit by bumping `ver:catalog`, never read a quantity from cache for a write, Redis down never fails a request.
- 26–33: thin controllers, Contracts records, `Result<T>`, `CancellationToken`, paging max 100, index per filter/sort documented, projections + `AsNoTracking`, no N+1.
